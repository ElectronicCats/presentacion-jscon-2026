Tecnologías · Meshtastic

Mensajes sin internet
ni red celular

Meshtastic es un proyecto de código abierto que usa radios LoRa para formar una red mesh de mensajería.

Radios LoRa

Los nodos se hablan por radio, a larga distancia y con muy poca energía. Sin antenas de celular ni internet.

Una red mesh

Cada nodo puede retransmitir lo que oye, así que la red crece con cada nodo nuevo.

Tu celular como pantalla

La app (Android, iOS o web) se conecta al nodo por Bluetooth para leer y escribir mensajes.

  • Mensajes de texto, posición y telemetría
  • Firmware para ESP32 y nRF52
  • Mensajes cifrados con AES por canal

El canal del badge usa la clave por defecto de Meshtastic: sirve para el taller, pero no es privado.

9 / 41
Tecnologías · Meshtastic

Cliente · Router · híbridos

Cliente

Es un rol de nodo, no la app del celular. Que retransmita depende del rol y de la configuración; la app se conecta por Bluetooth, USB o Wi-Fi según el equipo.

Router / repetidor

Nodo configurado para priorizar el reenvío. Puede ampliar la cobertura; pide buena ubicación y configuración adecuada.

CLIENT_MUTE y otros

CLIENT_MUTE no retransmite paquetes de otros nodos. Un mismo equipo puede dar interfaz y radio; el reenvío depende del rol.

Tecnologías · Meshtastic

Cómo viaja un mensaje

0 / 5

Un mensaje, varios saltos

En una malla cada nodo puede retransmitir lo que oye. Avanza con las flechas y sigue un mensaje desde el nodo A.

El nodo A envía

El mensaje sale por LoRa con un límite de 3 saltos. Lo oyen sus vecinos directos: B y C.

Primer salto

B y C lo retransmiten. Ahora lo oyen D, E y F, que A no alcanzaba.

Segundo salto

D, E y F lo retransmiten y llega a G y H. Los mensajes repetidos se descartan.

Tercer salto

G y H lo retransmiten por última vez. I lo recibe, pero el límite de saltos llegó a 0: ya no lo reenvía.

Fuera de alcance

J queda más allá del límite y no lo recibe. Por eso un mensaje no puede circular sin fin.

Tecnologías · LoRa

LoRa: Long Range

  • Tecnología inalámbrica de largo alcance y bajo consumo. Su capa física usa la modulación Chirp Spread Spectrum (CSS).
  • La desarrolló Cycleo; Semtech la adquirió en 2012 y fabrica los transceptores.
  • Cada región tiene su banda: EU868, US915, AS923 o cerca de 433 MHz. El badge usa 915 MHz.
  • LoRaWAN es un protocolo de red que puede usarla; Meshtastic usa LoRa directamente, sin gateways.

¿De qué depende el alcance?

Más alcance se paga con menos velocidad: LoRa envía mensajes cortos.

12 / 41
Tecnologías · LoRa

Lo que LoRa puede hacer

Alcance

Varios kilómetros en condiciones favorables. Lo deciden el entorno, las antenas y la configuración.

Consumo

Años de batería si transmite poco y duerme entre eventos. Depende del ciclo de trabajo.

Baja tasa

De cientos de bit/s a decenas de kbit/s, según SF, BW y codificación. Ideal para mensajes cortos.

Robustez

Con ciertas configuraciones demodula señales por debajo del nivel de ruido.

Propagación

Las frecuencias sub-GHz ayudan en algunos entornos, pero paredes y obstáculos también atenúan.

Capacidad

Los nodos útiles dependen del tráfico, el tiempo en aire, los canales y las reglas regionales.

Control con JavaScript

Cómo habla JavaScript con el badge

  • Es el API serie estándar de Meshtastic: no hay firmware ni mensajes nuevos.
  • Cada orden es un protobuf armado a mano, dentro de un paquete de malla dirigido al propio badge.
  • Una trama de cuatro bytes de cabecera separa los mensajes en el flujo USB.
  • El navegador abre el puerto con Web Serial: Chrome o Edge, un clic del usuario.

Control con JavaScript · Web Serial

Abrir el puerto serie desde JavaScript

  • requestPort abre el selector del navegador. Solo funciona tras un clic del usuario.
  • El filtro 0x303a es el fabricante del ESP32-S3: solo aparece el badge.
  • readable y writable son flujos de bytes (Uint8Array), sin texto.
  • El puerto es exclusivo: una sola pestaña o programa a la vez.

Código real: badge-canvas.js · BadgeLink.request(), open(), _readLoop()

Web Serial en cuatro pasos

// 1 · Pedir el puerto (dentro de un clic)
const port = await navigator.serial.requestPort({
  filters: [{ usbVendorId: 0x303a }]
});

// 2 · Abrirlo
await port.open({ baudRate: 115200 });

// 3 · Un escritor y un lector
const writer = port.writable.getWriter();
const reader = port.readable.getReader();

// 4 · Leer sin parar
for (;;) {
  const { value, done } = await reader.read();
  if (done) break;
  rx = concat(rx, value);  // bytes crudos
  deframe();                 // busca 94 c3
}

Control con JavaScript · Web Serial

Enviar y leer tramas

Enviar · el cable no sabe dónde termina un mensaje

const bytes = new Uint8Array([
  0x94, 0xc3,           // inicio de trama
  payload.length >> 8,    // largo: byte alto
  payload.length & 0xff,  // largo: byte bajo
  ...payload              // ToRadio (protobuf)
]);
await writer.write(bytes);

Leer · los trozos USB no respetan los mensajes

// 1 · buscar el inicio 94 c3
while (!(rx[i] === 0x94 && rx[i+1] === 0xc3)) i++;

// 2 · leer el largo y esperar el resto
const len = (rx[i+2] << 8) | rx[i+3];
if (rx.length < i + 4 + len) return;

// 3 · cortar la trama y seguir
const frame = rx.slice(i+4, i+4+len);
rx = rx.slice(i + 4 + len);
dispatch(frame);   // FromRadio

Lo que no empieza con 94 c3 es texto de consola del firmware y se ignora. El largo máximo es 512 bytes: si dice más, el flujo se desalineó y se busca otro inicio.

Un paquete, byte a byte

Mostrar «Hola» en el badge: estos 21 bytes viajan por el cable USB.

Trama
94 c3inicio de trama
00 11largo: 17 bytes
ToRadio · MeshPacket
0a 0fpacket (campo 1), 15 bytes
15 db 20 82 8bto: nodo 0x8b8220db (fixed32)
22 08decoded (campo 4): un Data de 8 bytes
Data
08 01portnum = 1: texto
12 04payload, 4 bytes
48 6f 6c 61«Hola» en ASCII

Cada campo es clave + valor; la clave es (número de campo × 8) + tipo. Los enteros usan varint y el destino ocupa cuatro bytes en little-endian.

Taller · Ejemplo 1

Cambiar el nombre y reconectar

  • setOwner guarda el nombre y reinicia el badge.
  • El puerto USB cae unos segundos: la página debe avisar y reconectar.
  • getPorts() devuelve los puertos que ya autorizaste, sin otro clic.
  • Reintenta cada 2 s; el badge tarda ~10 s en volver.

Reconexión después del reinicio (simplificada)

await device.setOwner('Ana Pérez', 'AP');   // reinicia

for (let i = 0; i < 12; i++) {
  await sleep(2000);
  const [port] = (await navigator.serial.getPorts())
    .filter(p => p.getInfo().usbVendorId === 0x303a);
  if (!port) continue;
  try {
    link = new BadgeCanvas.BadgeLink(port);
    await link.open();
    device = new BadgeControl.Device(link);
    await device.readState();   break;
  } catch (_) {}
}
